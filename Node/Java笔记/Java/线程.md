## 进程：是程序的一次静态执行过程，占特定的地址空间，占用一个资源，进程间切换开销大，一个应用程序可以同时运行多个进程；进程也是程序的一次执行过程，是系统运行程序的基本单位

## 线程：是进程中一个单一的连续控制流程，共享同一个空间，但抢占同一资源，线程间的通信是在同一地址空间上进行，可称为轻量级进程，进程间切换开销小

## Thread类
- 可以理解为java中用于管理线程的一个类，封装了操作系统提供的线程管理API
- 每个由java代码创建的线程都可视为Tread类的一个实例化对象，来描述线程的信息
- Thread类可以被看作是对操作系统线程管理API的进一步操作
- java没有自己的线程,java线程是内核线程一对一绑定的，最新版本的jdk有虚拟线程也是在这个基础上的一个单线程上进行了任务划分单线程虚拟线程，也叫携程。可以理解java就是没有操作网络 线程io能力，底层jdk封装了一套逻辑去和操作系统交互
- 打开源码，有native标志的方法，比如线程启动的方法start（），他的方法里面调用了start0（）这个方法，这个方法是native的，在c++里面是有一个操控线程的方法也叫start0（）的，但是**java要声明一下**。即：就是java写的都是**应用层**，操作系统他有自己的操作规范，作为调用，是不可以去实现具体线程如何调用的系统底层，只能交给操作系统，相当于发命令让你去启动线程，暂停线程这些，但是具体的怎么调用，操作系统去搞，和java代码就没有关系了。只是提交了请求

## 线程状态（生命周期）：
- 有五种：创建（新生）--》就绪--》执行--》终止，，还有阻塞
- 新生状态（new thread() ）：在创建线程对象后，没启动前；有自己的内存空间，但没有资源
- 就绪状态（runnable）：t1.start(); ，线程已启动，具备运行条件，但没有资源（cpu），准备开始执行，但没有执行，表示在调用start方法后，所有线程添加到一个就绪的队列中，等待cpu时间片
- 执行状态（running）：当进程获取资源后，就绪队列中所有线程抢占资源去执行，执行run方法过程为执行状态，没有意外则会一直运行
- 死亡状态：1、线程正常运行后结束，自然死亡  2、抛出异常，人为中断stop方法，为异常终止 
- 阻塞状态：
	- 等待阻塞：运行时遇到wait()方法，JVM将该线程放到等待池中
	- 锁阻塞状态：该线程尝试获取锁而该对象锁被占用，从而进入Blocked状态，会被JVM放入锁池中
	- 其他阻塞：进入方法有
		- 1、sleep方法或join方法  
		- 2、等待IO资源；
		- 3、程序运行时发生异常导致无法运行，当阻塞消除后，队列会重新回到就绪队列中等待抢占资源，
		- 4、人为的join()方法

## 礼让（Thread.yield()方法），让当前线程礼让

## 线程等待wait（）
- 必须在synchronized中使用，使用时会释放锁，没锁会抛出异常
- wait是Object类的方法，而sleep是Thread的方法
- 以同步锁来控制，Object.wait();
- wait(1000),进行等待1秒，时间到后如果没有被notify唤醒，则自动唤醒，如果时间到前被唤醒了，则立刻停止等待并执行
- wait不是线程的操作，是多线程的通讯


## 唤醒线程notify（）

## 悲观锁和乐观锁（一种思想）
- 悲观锁
	- 假设并发更新遇到冲突，则发生悲观锁，不管冲突是否真的发生，都会使用锁，锁住读取的记录，阻止其他事物读取和更新这记录，其他事物会堵塞，直到该事务结束
	- 悲观锁是在数据库的事务隔离的基础上独享占有的资源，保证读取数据的一致性，避免修改数据丢失，悲观锁可以使用事务的Repeatable Read事务，满足悲观锁的需求
- 乐观锁
	- 不会锁任何东西，不依赖数据库的事务机制，乐观锁是应用系统层面的东西，大多数基于数据版本（Version）的记录机制实现
		- 数据版本
			- 是数据增加一个版本标识，在基于数据库表的版本解决方案中，一般是通过数据增加Version字段来实现，读取数据时将版本号一起读出，后续更新时，对此版本号加一，根据版本号对比，进行更新


## 线程加载（ThreadLocal）（复制的，不一定对）
- 主要为变量在每个线程中创建一个副本，每个线程都可以访问自己的内部副本变量
- 变量副本存储
	- 每个线程都有一个threadLocals成员，引用类是ThreadLocalMap，以 ThreadLocal 和ThreadLocal 对象声明的变量类型作为参数，所使用的 ThreadLocal 变量的实际数据，通过 get 函数取值的时候，就是通过取出 Thread 中 threadLocals 引用的 map，然后从这个 map 中根据当前 threadLocal 作为参数，取出数据。也就是说其实不同线程取到的变量副本都是由线程本身的提供的，存储在线程本身，只是借助 ThreadLocal 去获取，不是存放于 ThreadLocal
- 变量副本（每个线程中保存的map的变量）声明和初始化
	- 当线程中的 threadLocals 成员是 null 的时候，会调用 ThreadLocal.createMap(Thread t,T firstValue)创建一个 map。同时根据函数参数设置上初始值。也就是说，当前线程的threadlocalmap 是在第一次调用 set 的时候创建 map 并且设置上相应的值的。在每个线程中，都维护了一个 threadlocals 对象，在没有 ThreadLocal 变量的时候是 null的。一旦在 ThreadLocal 的 createMap 函数中初始化之后，这个 threadlocals 就初始化了。以后每次 ThreadLocal 对象想要访问变量的时候，比如 set 函数和 get 函数，都是先通过getMap(Thread t)函数，先将线程的 map 取出，然后再从这个在线程（Thread）中维护的map 中取出数据或者存入对应数据
- 不同的线程局部变量，比如说声明了 n 个(n>=2)这样的线程局部变量 threadlocal，那么在 Thread 中的 threadlocals 中是怎么存储的呢？threadlocalmap 中是怎么操作的？在 ThreadLocal 的 set 函数 中，可 以看到， 其中的 map.set(this, value)把当 前的threadlocal 传入到 map 中作为键，也就是说，在不同的线程的 threadlocals 变量中，都会有一个以你所声明的那个线程局部变量 threadlocal 作为键的 key-value。假设说声明了N 个这样的线程局部变量变量，那么在线程的 ThreadLocalMap 中就会有 n 个分别以你的线程局部变量作为 key 的键值对


## 如何防止ThreadLocal 如何防止内存泄漏
- 每次使用完 ThreadLocal，都调用它的 remove()方法，清除数据在使用线程池的情况下，没有及时清理 ThreadLocal，不仅是内存泄漏的问题，更严重的是可能导致业务逻辑出现问题。所以，使用 ThreadLocal 就跟加锁完要解锁一样，用完就需要清理。

## synchronized 用在静态和非静态方法的区别
- 当 synchronized 修饰一个 static 方法时，多线程下，获取的是类锁(即 Class 本身，注意:不是实例)，作用范围是整个静态方法，作用的对象是这个类的所有对象。当 synchronized 修饰一个非 static 方法时，多线程下，获取的是对象锁(即类的实例对象)， 作用范围是整个方法，作用对象是调用该方法的对象简单说 synchronized 关键字加到 static 静态方法上是给 Class 类上锁，简称类锁(锁的事当前类的字节码)而加到非 static 静态方法是给对象加锁
