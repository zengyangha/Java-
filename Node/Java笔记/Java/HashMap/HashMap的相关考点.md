
# 点此回到[[Map]]

## HashMap的put实现：
- 先计算key的hashcode值
- 如果散列表为空，则调用resize（）来初始化散列表
- 如果没有发生碰撞（hashcode值相同），则直接添加元素到散列表
- 如果发生碰撞
	- 若key或者value相同，则替换旧值
	- 若是红黑树结构了，则调用数的插入方法
	- 若是链表结构，则循环遍历直到链表某个节点为空，用尾插法插入，插入后判断链表个数是否达到红黑树的阈值8，或者循环遍历时遇到相同的内容并覆盖

## hashmap的get实现
- 对key的hashcode进行hashing，进行与运算计算下标，获取bucket位置，如果在桶的首位上就直接找到并返回，不然在树中或链表中遍历找，有hash冲突则利用equals得到去遍历链表查找节点

## hashMap的扩容规则
- 判断旧数据的容量是否大于0来判断是否初始化
- 进行初始化时先判断是否调用无参构造器，是则使用默认的大小（16）和阈值（12），否则使用调用构造函数中初始化的容量，
- 扩容，扩容两倍，然后将元素重新进行与运算，然后复制到新的散列表中
- 即扩容需要新分配个数组，新数组是旧结构的两倍长，然后遍历旧结构，然后把所有元素重新hash分配到新的结构中


## 哈希碰撞，两个对象的hashcode相等，若key值相同则覆盖，不然链接到表后面

## 为什么会引入红黑树
- 如果元素小于8个，查询成本高，新增成本低，如果大于8个则相反
- 木桶效应，要重视短板，数组+链表在庞大的数据中很难保证元素均匀分布，而且遍历的时间也长，时间复杂度高O(n)，而引入红黑树能将查找的时间复杂度降为O(logn)
